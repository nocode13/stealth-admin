# Импорт каталога из Telegram + прайса

Инструмент живёт только в ветке `tools/catalog-import` и в `main` не уходит. Состоит из двух частей:

1. **`prepare.py`** (локально, Python) берёт экспорт Telegram-канала и прайс `.xlsx` и делает следующее:
   - разбирает посты: код, объём, PP, какое фото бирка, какое растение (Claude);
   - сопоставляет растения с каталогом системы, даже без SKU и с другими названиями (Claude по
     названиям, затем по фото);
   - пишет названия и описания RU/UZ/EN для новых каталогов (Claude);
   - убирает фон с фото растения и заливает белым (rembg).

   Результат лежит в `public/catalog-import/<batch>/`.
2. **Страница «Импорт каталога»** (`/catalog-import`, только SUPER_ADMIN) в локально запущенной админке.
   По каждой карточке выбираешь продавца, проверяешь матч, цену и остаток и жмёшь **Approve**.
   Применение идёт через обычные admin-эндпоинты:
   1. каталог (новый или существующий, плюс описание, если его не было);
   2. позиция (новая или обновление `sku`/`costPrice`/`stock`, пустой вариант дописывается);
   3. старые фото позиции удаляются, заливаются белое фото и видео;
   4. статус `ACTIVE`.

   Без approve ничего не меняется.

## 1. Экспорт канала из Telegram

1. Поставь **Telegram Desktop**: <https://desktop.telegram.org> или `brew install --cask telegram-desktop`.
   Нужен именно он, в приложении «Telegram» из App Store нет полноценного экспорта.
2. Открой канал, нажми `⋮` в правом верхнем углу и выбери **Export chat history**.
3. Отметь **Photos**, **Videos** и **Files** (в канал фото кидают файлами), **Size limit** поставь на
   максимум. Format — **HTML** или **Machine-readable JSON**, скрипт понимает оба.
4. Получится папка `ChatExport_…/`: `messages.html` + `files/` (или `result.json` + `photos/`, `video_files/`).

Пост канала — альбом: фото бирки, 2 фото растения, видео, в подписи код. Посты разделяются по подписи
и паузе больше 10 с (альбом иногда переваливает через секунду). Нестандартные посты будут с
предупреждением на карточке.

## 2. Установка (один раз)

```bash
cd tools/catalog-import
python3.12 -m venv .venv          # rembg/onnxruntime: Python 3.10–3.12
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # заполнить ключ Claude и доступ к API (только чтение)
brew install ffmpeg               # убирает звук из видео и проверяет длину
```

В `.env`:
- `ANTHROPIC_API_KEY` — ключ Claude.
- `API_BASE_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` — логин SUPER_ADMIN. Скрипт только читает каталог и
  позиции для сопоставления (GET).

## 3. Подготовка партии

```bash
source .venv/bin/activate

# Проверить, как собрались альбомы (ожидаем 2 фото + 1 видео + подпись)
python prepare.py --export ~/Downloads/ChatExport_2026-10-19 --excel "../../../прайс 18,10.xlsx" --batch test --inspect

# Сравнить модели удаления фона на 10 постах → public/catalog-import/test/compare/*.jpg
python prepare.py --export ... --excel ... --batch test --compare 10

# Пробная партия на 10 постах
python prepare.py --export ... --excel ... --batch test --limit 10

# Прод пачками по 10: пачка K = посты (K-1)*10+1 … K*10, партия называется prod-0K.
# Следующую пачку готовь после approve предыдущей: снимок каталога старше 10 минут
# перечитывается сам, и новые каталоги из прошлой пачки участвуют в сопоставлении.
python prepare.py --export ... --excel ... --batch prod --chunk 1
python prepare.py --export ... --excel ... --batch prod --chunk 2   # и так далее

# Отчёт сопоставления «прайс → каталог (уверенность, причина)»; он же лежит в match-report.tsv
python prepare.py --batch 2026-10-san --match-report
```

Всё кэшируется в `cache/`: повторный прогон не платит за Claude и не пересчитывает фон. Если
поменялся каталог в системе, добавь `--refresh-snapshot`. Если поменялась модель фона
(`--bg-model isnet-general-use`), добавь `--force-bg`.

Как устроено сопоставление (один раз на растение, а не на каждый размер):
1. В системе есть позиция с этим SKU — берём её каталог.
2. Claude получает весь список каталогов (кэшируемый блок) и названия всех размеров из прайса.
   Возвращает до 5 кандидатов. Транслит и опечатки допустимы, разные сорта — нет.
3. Claude сравнивает фото из канала с обложками кандидатов и выдаёт выбор, уверенность
   (`high`/`medium`/`low`) и причину. При `low` карточка по умолчанию предлагает новый каталог.

## 4. Approve в админке

В `stealth-admin/.env.local` (файл в gitignore):

```bash
VITE_API_BASE_URL=/prod-api
IMPORT_PROXY_TARGET=https://<api-домен-прода>   # для локального бэкенда: http://localhost:3000
```

Затем `pnpm dev`, логин SUPER_ADMIN и раздел **«Импорт каталога»** в меню. Дев-сервер проксирует
`/prod-api` на прод и переписывает cookie сессии под localhost (см. `vite.config.ts`).

На странице:
- **Курс** — `costPrice = розница из прайса ($) × курс`. Розницу на витрине считает система по
  ступеням наценки, рядом показана подсказка «≈ на витрине».
- **Продавец, категория, подкатегория, страна** — значения по умолчанию для партии; на карточке
  можно поменять. Подкатегория нового каталога подбирается по роду.
- **Карточка**:
  - фото растения (с белым фоном или оригинал), бирка и видео;
  - все строки прайса по коду (с разных листов, расхождения подсвечены);
  - вариант (объём, PP → `stemCount`, высота по нижней границе);
  - каталог: кандидаты Claude с обложками и причиной, плюс поиск;
  - позиция продавца: тот же вариант / вариант не заполнен / новый размер.
- **Approve** применяет карточку. За раз выполняется одна карточка, чтобы следующий размер того же
  растения увидел только что созданный каталог. Ошибка показывается на карточке, и **Повторить**
  продолжает с упавшего шага, без дублей.
- Итоги approve и пропуски хранятся в `localStorage` браузера по партии. Источник правды — система:
  перед созданием позиция ищется по SKU у продавца.

## Формат партии

`public/catalog-import/<batch>/manifest.json` — его тип описан в
`src/pages/catalog-import/lib/manifest.ts`. Медиа лежит в `media/<id поста>/`: оригиналы `0.jpg`, `1.jpg`, …,
фото растения с белым фоном `white-<n>.jpg` (до 1600 px; на витрину идут все, лучшее первым) и
`video-muted.mp4` — видео без звуковой дорожки (видеопоток не перекодируется).
